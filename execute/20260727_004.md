TASK: Fix False-Positive Invoice Sync Block in DeliveriesController
Please update DeliveriesController.cs in amtemeterai.Api to ensure new invoice records from SAP are inserted into the database without being incorrectly blocked.

ISSUE
When syncing an invoice (e.g., BC Delivery), SAP returns a valid payload with message: "Invoice already created previously".

The controller currently inspects SAP's message string first and returns "No new BC Billing document found in SAP...", even though the invoice does NOT exist in PostgreSQL yet.

CORRECT ORDER OF OPERATIONS
When processing the SAP response payload (e.g., sapResponse.SapInvoiceNumber):

Query Local Database First:
Check if an invoice with sapResponse.SapInvoiceNumber exists in _db.Invoices.

Branch 1: Invoice DOES NOT exist in DB (existingInvoice == null)

Do NOT block or throw an error based on sapResponse.Message.

Proceed directly to create, map, and insert the new Invoice entity into _db.Invoices.

Call await _db.SaveChangesAsync() and return 200 OK success.

Branch 2: Invoice DOES exist in DB (existingInvoice != null)

Check the status of existingInvoice:

If ACTIVE (Not Voided / Not Canceled): Return 200 OK with message: "Invoice already synced."

If VOIDED or CANCELED: Return 400 Bad Request with message: "No new BC Billing document found in SAP. Please create the BC Billing in SAP first before syncing."

CODE IMPLEMENTATION
C#
// 1. Check local DB by SAP Invoice Number
var existingInvoice = await _db.Invoices
    .FirstOrDefaultAsync(i => i.InvoiceNumber == sapResponse.SapInvoiceNumber);

// 2. If it already exists in DB, evaluate local status
if (existingInvoice != null)
{
    bool isVoidedOrCanceled = existingInvoice.Status == Invoice.InvoiceStatus.Voided 
                           || existingInvoice.Status == Invoice.InvoiceStatus.Canceled;

    if (isVoidedOrCanceled)
    {
        _logger.LogWarning("Sync blocked for Delivery {DeliveryNumber}: SAP returned voided invoice {InvoiceNumber}.", 
            deliveryNumber, sapResponse.SapInvoiceNumber);

        return BadRequest(new
        {
            success = false,
            message = "No new BC Billing document found in SAP. Please create the BC Billing in SAP first before syncing."
        });
    }

    return Ok(new
    {
        success = true,
        message = "Invoice already synced.",
        invoiceNumber = existingInvoice.InvoiceNumber,
        billingDate = existingInvoice.InvoicedDate
    });
}

// 3. If existingInvoice == null: Proceed to Save New Invoice directly!
var newInvoice = new Invoice
{
    InvoiceNumber = sapResponse.SapInvoiceNumber,
    DeliveryHeaderId = delivery.DeliveryID,
    InvoicedDate = sapResponse.BillingDate,
    InvoiceAmount = sapResponse.AmountInvoice,
    Currency = sapResponse.Currency,
    Status = Invoice.InvoiceStatus.Active // or default active status
    // ... map remaining fields ...
};

await _db.Invoices.AddAsync(newInvoice);
await _db.SaveChangesAsync();

return Ok(new
{
    success = true,
    message = "Invoice successfully synced from SAP.",
    invoiceNumber = newInvoice.InvoiceNumber
});
ACCEPTANCE CRITERIA
If sapResponse.SapInvoiceNumber is not in _db.Invoices, it inserts into PostgreSQL successfully, ignoring SAP's message text.

Prevents DbUpdateException duplicate key errors by performing existence checks before insert.

Differentiates between active vs. voided local invoices when handling duplicate payload numbers.
