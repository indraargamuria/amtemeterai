Bug Fix: Race Condition / First-Try Failure on Non-BC Invoice Creation
Creating a Non-BC invoice fails on the first attempt and succeeds on the second attempt due to SAP DB commit latency (COMMIT WORK delay in SAP before fetching invoice details).

REQUIREMENT 2: Retry Loop with Delay for SAP Fetch Phase
Because SAP requires time to commit transaction data to DB tables (VBRK/VBRP), the immediate fetch call after invoice creation can return 404 or empty data on the first attempt.

Implement Retry Policy in C#:

After triggering the SAP create invoice function, wrap the subsequent fetch step in a retry loop.

Set maxRetries = 3 with a 1500ms delay between attempts using Task.Delay(1500).

If the fetch succeeds within 3 attempts, proceed to save the invoice record into OpexNOW DB and update the response.

If all retries fail, return a descriptive error message indicating that the SAP creation succeeded but sync timed out.

C#
var createResult = await _sapService.CreateInvoiceAsync(deliveryNumber);
if (!createResult.IsSuccess)
{
    return BadRequest(new { success = false, message = "Failed to trigger invoice creation in SAP." });
}

int maxRetries = 3;
int delayMs = 1500;
SapInvoiceFetchResult sapInvoice = null;

for (int attempt = 1; attempt <= maxRetries; attempt++)
{
    sapInvoice = await _sapService.FetchInvoiceDetailsAsync(createResult.GeneratedInvoiceNumber);

    if (sapInvoice != null && sapInvoice.IsSuccess)
    {
        break;
    }

    if (attempt < maxRetries)
    {
        await Task.Delay(delayMs);
    }
}

if (sapInvoice == null || !sapInvoice.IsSuccess)
{
    return StatusCode(500, new { 
        success = false,
        message = "Invoice was created in SAP, but fetching details timed out. Please refresh or try syncing again." 
    });
}
